# Bilibili-oversea 浏览器扩展 2.3.5

适用于 Chrome 111+、Edge 111+ 及兼容 Manifest V3 的 Chromium 浏览器。

这是 Bilibili-oversea 的独立实现，不包含或运行其他浏览器扩展的源码。页面观察、候选校验、Range 测速、
标签页级会话规则、缓冲健康检查和弹窗界面均位于本目录，并由本项目维护。

## 安装

完整步骤见：<https://limitedrush.online/projects/bilibili-oversea#browser-guide>

1. 下载并解压 `bilibili-oversea-browser-v2.3.5.zip`。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”。
4. 选择解压后包含 `manifest.json` 的目录。
5. 打开或刷新 B 站视频页面，播放几秒，再点击扩展图标查看测速结果。

已安装用户：将新包解压到原扩展目录，在扩展管理页点击“重新加载”，然后刷新已有的 B 站播放页。只更新文件或重开弹窗不会更新已经运行的后台及页面脚本。首次升级会弃用旧版测速缓存，重新获取可信结果；模式与排除设置保留。

## 2.3.5：关闭标签后重新打开视频

- 旧标签关闭时取消测速下载、丢弃旧播放状态并撤销该标签规则。缓存读取/规则安装中途关闭也不会由迟到结果重新建立状态或启动第二轮测速；规则变更按标签串行，不堵塞其他标签。
- 有有效主机缓存时，新标签先复用最优线路、不等待完整测速；实际视频识别后，在至少 12 秒安全缓冲时自动复核。没有可用缓存时按原预算完整测速；卡顿确认后仍先轮换已验证备用节点。
- 三条不同低播放量视频的真实 Edge 生命周期检查覆盖正常关页、新标签复核、测速中关页和下一标签独立冷测速。受控消息验证备用轮换，小媒体请求确认新标签的重定向；不等于自然卡顿或整段流畅验收。详见 `qa/ACCEPTANCE-2.3.5.md`。
- 没有新增权限、弹窗、持久数据或更改 2.2.0 数值策略；Akamai 仍仅观察/原始直通，关闭、原始或固定模式仍遵从用户设置。

## 2.3.4：识别、候选收集与固定页脚

- 视频身份只跟随视频路径、分 P 与番剧 episode；追踪参数或 hash 不再清空发现数据、重复复核或锁住加载卡片。复用 MSE 播放器时，实际 playing 事件也能完成展示交接，无需等待第二次 loadedmetadata。
- 展示与健康监测都选择主播放器；移除播放器不继续监测旧元素，重新出现不重复绑定监听器。仅有一个主播放器时不为每次 DOM 更新强制读布局。
- 在 fetch 发出或 XHR send 阶段识别实际视频请求、当前 Range 和最高画质，不等待大分段下载完成；SSR 初始值晚于 document-start 时即时补读。请求阶段不伪报实际响应节点，响应确认仍分开。
- 保留完整 DASH 视频描述中经校验的备用主机，不因只收集前八个 URL 而遗漏；默认三节点、最多八候选及测速预算不变。新增已发现节点仍受原安全缓冲和维护机制约束。
- Akamai 可以作为只读来源显示，不能固定/排除/测速，不冒充第四个可用备用。列表汇总区分候选与仅观察来源。
- 弹窗采用稳定的 400×600 框架，页脚固定、仅候选区滚动；重测显示和长错误不会将列表挤到页脚之外。没有 waiting 事件但进度持续停止时显示“播放停滞”，不亮正在播放呼吸灯；此展示判定不会盲目触发换 CDN。
- 测试改为多条低播放量视频、从头顺序播放、禁用浏览器缓存，联合记录进度停滞、输出帧、seek、缓冲和请求取消。CDN 缓存无法控制、headless 不等同于用户前台，单次通过不证明永久零卡顿。

## 2.3.3：真实播放状态面板

- 主卡片显示真实播放/暂停/缓冲/跳转/结束状态、视频标题、当前帧分辨率、缓冲秒数和播放进度；只在真实播放时点亮呼吸灯，支持减少动态效果。
- 播放状态与测速/选路状态分开。目标节点与实际节点尚不一致时单独显示目标，不把规则就绪当作已确认播放。
- 删除常驻解释性小字；全部候选保留在独立滚动列表中，并显示可用与总数；保留固定、排除、恢复、重测和诊断功能。
- 重测过程中保留候选目录和滚动位置；旧测量标明“上次”，预置及已发现但未测的节点明确标记，不虚构速度。Akamai 原始直通保留未测预置目录，但不开放跨 CDN 固定或重测。
- 弹窗打开期间每秒读取本页只读信息，关闭即停止；不增加后台轮询、请求、权限或持久数据。标题和播放信息不进入缓存或复制诊断。
- UI 与安装/教程入口统一指向个人网站。网站页面已存在，但其安装资源版本由网站维护任务单独更新，不能视为本包发布即自动上线。
- `worker.js`、`engine.js`、`network-probe.js` 和 `page-bridge.js` 未修改；`content.js` 仅增加独立只读展示通道。2.2.0 选路、测速与恢复逻辑保持不变。

## 2.3.2：固定 2.2.0 策略，修正测量与恢复

- 保留 2.2.0 的候选默认值、吞吐量/首包排序、测速大小与超时、切换增益、缓存期限及缓冲阈值。基线测试锁定这些参数；不是把旧版存在问题的实现逐字回滚。
- 继续保留独立后台测速、取消与签名校验，及 2.3 的亮色界面、图标和真实弹窗尺寸修复。
- 区分 DASH 视频与音频；最高画质切换后重新复核实际视频，不拿音频或页面预先提供的另一档画质替代。
- 观察 B 站专用 Akamai 主机 `upos-hz-mirrorakam.akamaized.net`，沿用 2.2.0 的原始直通，不自动跨 CDN 改道，也不增加主机权限。实测退化的 Akamai 跨 CDN 自动改道方案已撤回。
- 记录实际响应主机和当前视频片段的 Range 起点；仍按旧版有限字节预算测速，而非总从文件头测量。弃用旧测量缓存 V4，启用 V5。
- 新出现且未测过的受支持 CDN 在安全缓冲后纳入完整候选测试；固定节点时同步更新源主机覆盖范围。Akamai 只观察，不参与候选测速或固定；该视频弹窗明确显示原始直通，重测禁用，避免把音频优化冒充视频优化。
- 插件恢复动作本身卡在 seek 时，以原有 8 秒冷却继续轮换；播放恢复、导航或用户交互会取消这个看门狗，不接管用户手动 seek。

## 2.3.1 修复

- 在真实 Edge 工具栏弹窗中复现并修复 32px 窄条：固定根元素与主体的固有宽度为 400px，避免 `100vw` 与自动尺寸计算循环。
- 测速改用独立后台请求，隔离播放重定向，校验实际响应节点；固定线路不再污染其他节点的测速结果。
- 重测期间仍可暂停或切回原始；后台唤醒会无下载地重建媒体状态；换视频、离开及关闭标签页会取消旧任务。
- 排除节点即使未出现在新测速结果中也保留“恢复”入口。
- 可重复执行的真实弹窗验收脚本及覆盖范围见仓库中的 `qa/ACCEPTANCE.md`。

## 2.3 更新

- 亮色毛玻璃工作台：浅灰、半透明白色与石墨色文字，无渐变；链路状态、自动/原始模式、Mbps 实测列表与可取消的重测。
- 自动模式优先复用缓存；仅“重测线路”强制重测。
- 切回原始、暂停、固定线路或换视频时取消旧测速，迟到的结果不会重新安装规则。
- 缓冲不足时跳过复核，不误判节点失败；自动模式卡顿恢复优先轮换备用节点。
- 跨平台标准 ZIP，根目录直接包含 manifest.json，并提供 SHA-256 校验文件。

## 工作方式

- 只读观察 B 站 `playurl`、`window.__playinfo__` 和浏览器资源时间线，页面桥接脚本不修改播放器数据；
- 每 10 秒进行一次无额外下载流量的页面/资源兜底扫描，用于发现 SPA 换视频和漏过的媒体请求；
- 从实际视频带签名的媒体 URL 派生候选请求；无缓存且只发现 DASH 预告地址时先原始直通，不阻塞开播；
- 内容脚本负责缓冲判断与取消，后台独立读取候选；仅后台发起的候选请求添加 B 站 Referer，不修改网页请求：最多 8 个候选各请求 128 KiB 初筛，再对前三名各请求最多 1 MiB 复测；
- 新视频立即使用三小时内的缓存最优节点；缓冲达到 12 秒后只用 256 KB 比较当前节点和最佳备用节点，此后每 15 分钟轻量复核一次；
- 仅为当前 B 站播放标签页添加 Chrome 会话重定向规则；
- 每 2 秒监测缓冲；低于 8 秒且持续快速下降，或经确认的 `waiting/stalled` 发生时，立即切换到下一个已验证节点并轻微回退；
- 完整成功结果缓存 3 小时，失败结果缓存 10 分钟；线路明显变慢、失败、网络变化、候选耗尽、出现未测过的实际 CDN、硬过期或手动重测时才完整测速；
- 支持自动、重测线路、固定节点、排除节点和恢复原始 CDN。

## 权限

- `activeTab`：打开弹窗时读取当前标签页；
- `storage`：保存模式、排除节点和本地测速缓存；
- `declarativeNetRequestWithHostAccess`：建立仅限当前播放标签页的临时 CDN 规则，以及仅限本扩展测速请求的 Referer 规则；
- 主机访问权限保持 2.2.0/2.3.1 范围：明确的 B 站页面、`*.bilivideo.com` 和 `*.mcdn.bilivideo.cn`。页面内只读观察 Akamai 响应无需增加媒体主机访问权限；切换规则不包含 Akamai。

不申请代理、Cookie、历史记录、`webRequest` 或 `<all_urls>` 权限，不包含遥测、广告、远程代码或后端服务。
