# Chrome / Edge 浏览器插件完整教程

Bilibili-oversea 2.3 是本项目独立实现的 Manifest V3 扩展。它只在 B 站播放页观察媒体地址，在本机对候选
受支持的 B 站 CDN 做小流量 Range 测速，并为当前播放标签页建立临时重定向规则。2.3.5 固定 2.2.0 的选路参数，保留独立测速与取消等正确性修复，修正主播放器、请求阶段及页面切换的识别，并保护关页后的迟到缓存/规则流程。

## 1. 下载

打开项目与安装页：<https://limitedrush.online/projects/bilibili-oversea>

网站更新到本版后，下载文件名应为 `bilibili-oversea-browser-v2.3.5.zip`；若仍显示旧版，以网站实际版本为准，不代表网站已经同步。压缩包根目录直接包含 manifest.json；同目录的 .zip.sha256 文件可用于核对传输是否完整。

浏览器不能直接加载 ZIP。先在文件管理器中把它完整解压到一个不会随手删除的目录，例如
`Documents/BiliCDNAuto`。打开该目录后应直接看到 `manifest.json`、`src` 和 `assets`。

## 2. 安装到 Chrome

1. 在地址栏输入 `chrome://extensions` 并回车。
2. 打开页面右上角的“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择刚才解压且直接包含 `manifest.json` 的目录。
5. 列表中出现 `Bilibili-oversea 2.3.5` 和播放三角/蓝色线路箭头图标，即安装成功。

## 3. 安装到 Edge

1. 在地址栏输入 `edge://extensions` 并回车。
2. 打开左侧或页面下方的“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择包含 `manifest.json` 的目录。
5. 确认扩展开关处于开启状态。

## 4. 固定插件图标

- Chrome：点击工具栏拼图图标，在 Bilibili-oversea 右侧点击图钉。
- Edge：点击“扩展”图标，在 Bilibili-oversea 右侧选择在工具栏中显示。

固定不是必须的，但会方便查看当前节点和手动重测。

## 5. 第一次运行

1. 打开 <https://www.bilibili.com> 的普通视频、番剧或课程播放页。
2. 如果安装扩展之前已经打开了页面，先刷新一次。
3. 开始播放视频；插件会立即监听播放接口，并每 10 秒做一次不下载媒体数据的兜底扫描。
4. 点击工具栏中的 Bilibili-oversea 图标。
5. 有缓存时直接使用缓存线路；没有缓存时先原始直通，发现实际视频地址后初筛，并在安全缓冲后复测。仅发现 DASH 预告地址时不抢先测另一档画质。

工具栏角标含义：`…` 正在测速，`A` 自动模式，`M` 固定节点，`—` 原始 CDN，`!` 测速失败。

## 6. 弹窗功能

- **自动**：清除手动固定，优先复用当前节点和缓存，不强制完整测速。
- **重测**：切回自动模式，使用当前视频地址重新测试；也可按 R。重测中保留节点目录与上次测量，不把上次结果伪装成新结果。
- **原始线路**：删除已知播放标签页的切换规则，使用 B 站原本分配的节点。
- **固定**：在测速结果中固定使用某个可用节点，并轻微回退播放位置以让后续请求立即采用新规则。
- **排除**：跳过该候选；若正在使用该节点，立即移除规则并选择其他可用线路。
- **自动维护**：后台使用自适应策略；新视频安全缓冲后轻量复核，并每 15 分钟再次复核，没有额外维护按钮。播放时不会自动弹出面板。
- **总开关**：关闭后移除切换规则，但保留本地设置。

每个 B 站播放标签页都有独立的临时规则；关闭标签页后对应状态会被清理。

关闭正在播放的标签，再打开另一条视频，无需重启插件：有效缓存先应用，新标签识别自己的视频并在安全缓冲后复核；无可用缓存则重新测速。即使旧标签关闭时正在测速，也会取消旧任务，不把旧结果挂到新标签。这里“自动复核”不是每次开视频都阻塞等待完整测速；关闭、原始或固定模式仍遵从你的设置。Akamai 的原始直通边界保持不变。

## 7. 判断是否工作

正常表现：

1. 弹窗展示视频标题、分辨率、缓冲、进度及播放状态；
2. 支持测速且已完成时，至少一个结果显示 Mbps 和首包时间；未测速不会捏造速度；
3. 当前线路区显示请求确认状态，节点区区分当前、固定、未测与不可用；“正在播放”与“已测速”是不同状态；
4. 缓冲低于 8 秒且持续快速下降，或发生经确认的 `waiting/stalled` 后，插件会立即尝试下一个已验证节点。

若实际视频使用 Akamai，弹窗会明确显示“原始直通”，并把它列为只读来源，不测速或固定，不再用音频节点冒充视频已经优化。这保留 2.2.0 的工作范围；该视频不会跨 CDN 改道，重测按钮禁用。默认三个海外候选；另有真实播放接口返回且受支持的 host 才会加入，最多八候选，不能保证每条视频都有更多节点。

判断卡顿不能只靠单个视频重复播放或没有 waiting/stalled 事件。应顺序测试多条未打开过、低播放量的视频，确认各自最高可选画质并从头播放，分别记录首次播放、重播、启动等待、中途停滞与拖动等待。禁用浏览器缓存也不能清除 CDN 缓存；原始线路与自动线路的比较应交换顺序，不能把暖缓存后的成功直接归因插件。后台解码、播放头和缓冲记录也不能完全代表前台屏幕的感受。

## 8. 更新插件

1. 下载新版本 ZIP。
2. 关闭浏览器，使用新版本文件替换原来的解压目录，目录路径不要改变。
3. 重新打开 `chrome://extensions` 或 `edge://extensions`。
4. 在 Bilibili-oversea 卡片上点击刷新图标。
5. 刷新已经打开的 B 站页面。

只覆盖文件或重新打开弹窗不能更新已经运行的脚本。2.3.5 不增加主机权限，保留模式与排除设置；升级后务必刷新已经打开的播放页。

## 9. 常见问题

### “加载已解压的扩展程序”时找不到 manifest

选择层级错了。应选择直接包含 `manifest.json` 的目录，而不是 ZIP，也不是它的上一级目录。

### 一直显示“等待视频”

- 确认网址是 `www.bilibili.com` 或 `m.bilibili.com` 的视频播放页；
- 安装/更新扩展后刷新播放页；
- 开始播放，并换到未缓存片段；
- 检查扩展详情页中的“网站访问权限”是否允许 B 站。

### 所有候选都不可用

当前视频签名、运营商线路或 B 站节点可能不接受候选 host。先选择“原始线路”，重新加载视频；稍后换网络或
换视频再测试。扩展不会绕过失效签名、地区限制或版权限制。

### 选择节点后视频反而停止

点击“原始线路”恢复，再排除该节点或点击“重测”。若问题持续，可在扩展管理页暂时关闭插件验证。

### 无痕模式不工作

扩展默认不能进入无痕窗口。如确实需要，可在扩展详情页手动允许；无痕使用会受到浏览器额外限制。

## 10. 卸载

在 `chrome://extensions` 或 `edge://extensions` 找到 Bilibili-oversea，点击“移除”。浏览器会删除扩展设置，
所有会话规则也会消失。随后刷新 B 站页面即可恢复平台原始行为。

## 隐私与权限

- 无服务器、账号、遥测、广告或远程代码；
- 不读取 Cookie、浏览历史或其他网站；
- 不使用浏览器代理权限；
- 完整媒体 URL 只保存在后台内存；
- 完整测速最多对 8 个候选各读取 128 KB 初筛，再对前三名各读取最多 1 MB 复测，理论上限约 4 MB；
- 新视频和每 15 分钟的轻量复核只比较两个节点，各读取最多 256 KB，并且要求至少 12 秒安全缓冲；
- 权限范围只覆盖明确的 B 站页面、`*.bilivideo.com` 和 `*.mcdn.bilivideo.cn`，不增加 Akamai 权限。运行时另限制媒体路径。
