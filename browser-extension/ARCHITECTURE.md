# Browser extension architecture

Version 2.3.4 is an independent Manifest V3 implementation maintained in this repository. The numerical routing policy is frozen to the user-approved 2.2.0 baseline by `tests/baseline-policy.test.js`; correctness fixes do not imply a byte-for-byte rollback.

2.3.4 recognizes video identity using pathname, part and episode rather than tracking parameters/hash. Main-player selection is shared by health monitoring and display and avoids layout reads for a single primary element. Native `playing` can complete an MSE display handoff without waiting for another metadata event. An idle playhead no longer keeps the playing beacon lit merely because no waiting event occurred; this is display-only, not a new recovery trigger.

The bridge announces actual request intent before native fetch or XHR send, bootstrapping late SSR descriptors if needed. Content validates and classifies it; the worker can benchmark the actually requested quality/offset before a large body completes, but intent never sets the confirmed response host. Worker wakeup can replay request intent. Complete validated video descriptors retain additional candidate hosts even beyond the first eight collected URLs. Default hosts, eight-host probe cap, byte/time budgets, ranking and Akamai passthrough remain unchanged. Only actual responses confirm a routed host.

1. `page-bridge.js` observes Bilibili play-url JSON and `window.__playinfo__` in the page main world without modifying them. It retains DASH video/audio descriptors and reports the actual fetch/XHR response host, original request and Range start, plus History API navigation. Native fetch responses and XHR headers are not modified.
2. `content.js` validates the bridge boundary, observes resource timing, performs a zero-download 10-second fallback rescan, samples playback buffer every two seconds, and coordinates safe-buffer probe batches and cancellation. On worker wakeup it can replay this page's known media URLs without a download. Navigation clears the URL sets and filters out resource entries from the previous video.
3. `worker.js` immediately applies a fresh cached winner, runs a 128 KB quick stage followed by a 1 MB sustained stage for up to three finalists when a full benchmark is necessary, performs 256 KB two-host verification in safe buffer windows, and owns session rules.
4. `engine.js` contains pure URL, settings, ranking and declarative-rule functions covered by tests.
5. `popup.*` is the light glass desktop interface; `popup-model.js` derives routing status without exposing signed URLs. `playback-view.js` separately formats a fresh playback snapshot. While open, the popup reads `get-playback-info` directly from this tab's isolated content script once per second; closing the popup destroys the timer. The read-only collector selects the main player, records native playback events, and reads title, current-frame dimensions, progress and buffer. Navigation suppresses old MSE player data until a new source or metadata arrives. No playback snapshot enters the worker, persistent storage, or copied diagnostics; stale snapshots cannot light the playing beacon. Mode selection reuses cached results; explicit retest requests a full benchmark.
6. `network-probe.js` performs independent worker fetches with `credentials: omit`, bounded Range requests and stream cancellation. Tab-scoped playback redirects cannot affect these requests. A session header rule scoped to this extension's initiator ID supplies the Bilibili referrer without changes to page requests. A response from another host is never ranked as a successful sample for the requested host. Cache schema V5 discards older audio/advertised-quality measurements. The byte budget is unchanged; the offset comes from the actual video segment when available, otherwise zero.

Media observation additionally recognizes the exact Bilibili Akamai host `upos-hz-mirrorakam.akamaized.net`, not shared Akamai domains. Routing target validation, cache and rules exclude Akamai, preserving 2.2.0 native passthrough. Cross-CDN Akamai routing was rejected after real HD playback regressed; small successful samples did not predict later segment reliability. No host permission was added. Both DNR rules additionally require the `/upgcxcode/` media path. DASH audio cannot replace the benchmark video source or claim the video's actual host. A changed actual video path invalidates pending probes and per-video verification. Cold DASH discovery waits for an observed video request rather than benchmarking another quality advertised by SSR; cached winners still apply immediately for eligible media.

Mode changes invalidate the worker run token and abort both content coordinators and worker fetch controllers. Light verification cancelled by navigation or a user action cannot apply its results. Insufficient buffer is a skipped sample, not a failed CDN. Playback stalls in automatic mode cancel background probes and rotate directly to a verified backup. Pausing or choosing a nonautomatic mode applies to all known playback tabs. Mode-setting commands start a cold benchmark in the background so pause/original controls remain available.

The native action popup uses an explicit 400px intrinsic root/body width. Do not constrain it with `max-width: 100vw`: Chromium's shrink-to-fit popup viewport can form an intrinsic-sizing feedback loop and collapse to 32px. Its shell is a fixed 600px flex column with a non-scrolling footer; only the candidate list and bounded error notice scroll. `qa/real-popup-check.js` targets the actual action-popup target, but is run only when visible test windows are explicitly acceptable. Quiet checks use a rendered extension page and must not be described as native-popup sizing acceptance.

`scripts/zip.mjs` creates reproducible ZIP32 archives using Node's built-in DEFLATE implementation. Entries use UTF-8 relative paths without a dot prefix. The packager publishes the archive atomically and writes a SHA-256 sidecar.

The popup candidate directory combines measurements with the unchanged default hosts and validated observed target hosts. Unmeasured rows cannot be fixed as a working CDN, are labelled distinctly, and never report throughput. Retesting preserves list scroll position and labels previous measurements. This presentation-only union does not add hosts to the worker's candidate pool or launch probes. Native Akamai passthrough can show untested presets without claiming they are available. Production runtime never opens a popup automatically; native popup opening belongs only to the explicit QA harness. After user feedback, ongoing QA uses the quiet, headless rendered-page harness instead.

No runtime code is downloaded. Closing a tab removes its state and rule; terminating the browser clears session rules.

The 10-second loop is not an unconditional benchmark timer. It discovers media and sends an activity heartbeat with buffer state. Successful full results remain eligible for three hours and failed results for ten minutes. A new video receives the cached winner immediately; after at least 12 seconds are buffered, the worker verifies only the current host and best backup. The same light verification is due every 15 minutes. A current-host failure, a backup at least 20% faster, network change, exhausted candidates, a newly observed untested target host, hard expiry, or an explicit user action promotes the work to a full benchmark. New-host maintenance waits for safe buffer and clears after the batch, including failure; it is not repeated every heartbeat.

Playback health is independent of benchmark expiry. A confirmed `waiting/stalled` episode rotates directly to the next verified host. Buffer is sampled every two seconds; when it is below eight seconds and drains by at least four seconds across four samples, recovery starts before the buffer reaches zero. User-initiated and recovery switches ask the content script to move playback back by 150 ms so the player creates a request that can use the new rule; an already-running request cannot be migrated.

A recovery-triggered seek can itself hang and suppress ordinary seeking-protected health checks. A watchdog reuses the existing 8-second cooldown and rotates again only if that recovery still has less than 0.5 seconds buffered. Playing, navigation, video replacement, pointer or keyboard interaction cancel it. A normal user-controlled seek is not retried by this watchdog.

For local troubleshooting, the content script exposes only the extension version, phase, selected host, most recently observed host, and rule-installed flag as `data-bili-cdn-auto-*` attributes on the page root. It never exposes a signed media URL or query string.
