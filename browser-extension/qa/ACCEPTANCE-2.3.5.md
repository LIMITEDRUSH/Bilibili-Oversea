# 2.3.5 关闭视频标签后重开 · 2026-10-04

## 请求与验收标准

观看 A → 关闭 A 标签 → 打开另一个 B 站视频 B。自动模式下，A 的状态、在途测速及规则不能残留或影响 B；B 独立识别实际视频，先复用有效缓存，再安全缓冲复核；无可用缓存时完整测速。确认卡顿后的备用轮换仍可工作。不是把每次新开视频变成阻塞式完整测速。

关闭/原始/固定模式遵从用户设置，Akamai 保留 2.2.0 原始直通，不以“确保测速”为由扩张未支持媒体的策略或权限。

## 失败回归与修复

普通关页/重开原先通过，但新增延迟夹具先使两个回归失败：缓存读取期间关闭会重建旧 active 状态；规则安装期间关闭会复活旧状态并继续第二阶段。随后又证实设置保存期间关闭存在同类复活问题。以上是确定性的生命周期错误，不是从自然卡顿反推。

- 取消始终使运行代次失效，覆盖缓存/设置等待而不只覆盖已启动的测速。
- 缓存、维护与恢复的异步交接检查状态身份；旧流程不会重新分配已删除状态。
- 规则操作按标签独立排队，已经发出的安装之后执行移除，不能遗留旧规则；旧完成回调不把新页 ruleInstalled 置假。无关标签不共用一个全局队列，完成后释放队列引用。
- 规则安装被取消后不继续第二轮测速；迟到结果不覆盖新标签已经写好的缓存。在途独立下载收到 abort。
- 设置/重测命令在异步保存后重新检查目标身份；全局设置保留，已关闭的目标不再接续动作。

新增八项回归覆盖正常关闭/暖缓存/复核/轮换、缓存延迟、规则安装延迟、心跳设置延迟、同标签重新加载、迟到旧测速不覆盖新缓存、关闭时取消下载、设置命令保存时关闭。原有后台唤醒、关闭/导航取消、Akamai、参数锁定及手机回归继续运行。

## 真实 Edge 生命周期检查

`qa/tab-lifecycle-check.js` 使用独立、静音的 headless Edge 配置，不操作用户日常窗口、不自动打开原生弹窗。三条视频按顺序创建/关闭不同标签；浏览器缓存禁用，插件缓存分别覆盖冷和暖路径。测试后关闭测试视频、恢复测试配置的原设置与缓存。这个脚本不进行整段播放验收。

首次运行：正常关页后的缓存应用和自动复核四项通过，但 QA 找不到隔离执行上下文而中断。修正 QA 为检查实际 runtime.id 后才发送受控消息，没有更改产品来迎合此失败。

## 边界

这里只验证关页/重开的功能链路与受控竞态，不证明所有视频永久不卡。视频重播、CDN 暖缓存和 headless 屏幕体验的边界不变，2.3.4 捕获的自然失败仍保留。未将未观测到的后台自然休眠、前台屏幕流畅、手机实机或独立 Chrome 全量验收写成通过。没有更改 2.2.0 候选默认值、排序、字节/超时、阈值或缓存期限，手机脚本不变。
