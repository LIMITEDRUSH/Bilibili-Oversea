# 2.3.1 发布验收 · 2026-10-04

最新 UI 与节点目录的检查见 [2.3.3 验收](ACCEPTANCE-2.3.3.md)，内核基线比较见 [2.3.2 验收](ACCEPTANCE-2.3.2.md)。以下保留 2.3.1 的历史记录，不代表新版已完成的检查。

## 结论与边界

Windows / Edge 154.0.4258.53 的独立测试配置中，源码和最终 ZIP 均进行了真实工具栏弹窗及公开 B 站视频验收。不是仅用固定宽度网页预览冒充扩展弹窗。未操作用户日常浏览器配置。

本次未完成真实 iPhone / Shadowrocket、Chrome 独立浏览器、付费番剧、全部清晰度、不同系统缩放及弱网组合的实机验收。移动端 25 项自动测试通过，但不能等同于手机实机通过。短期采样不证明所有网络、所有视频都永不卡顿；插件不能补足断网、总带宽不足或服务器拒绝请求。

## 已复现并修正

- 旧真实 action popup 的 viewport、body、shell 均只有 32px；`max-width:100vw` 与自适应弹窗尺寸循环相关。显式 400px 根宽度修复，实际重复开关后不再复现。
- 固定阿里后，旧页面内的腾讯测速被播放规则转去阿里，却报告腾讯成功。新版后台测速实测响应腾讯；同一播放页发起的媒体请求仍响应阿里，均为 HTTP 206。测速与播放切换确实分离。
- 最终截图暴露模式按钮与后台状态不同步；状态通知加入保存的设置后，外部切回自动会同步按钮高亮。
- 无额外 tabs 权限时，离开 B 站的 URL 可能不出现在更新事件中。改用页面 loading 事件清理，实际打开空白页后播放重定向规则为零、旧结果清空。
- 排除项失去恢复入口、冷测速锁住模式操作、后台唤醒缺媒体状态、关闭标签页后迟到任务，以及撤销规则失败却显示成功，均有修复及回归覆盖。

## 复测方法

1. `npm test`、`npm run check`、`npm run package:browser`。
2. 将 ZIP 解压到新的测试目录，在独立的 Edge/Chrome 配置中只加载该目录；不要用日常用户配置运行有设置切换的测试。
3. 使用 Playwright CLI 的持久会话；配置 headed Chromium、Edge channel、独立 userDataDir 和该扩展的 load-extension 参数。播放一个可访问的 B 站视频，等待可用候选出现。
4. 分别通过 `run-code --filename` 执行 `qa/live-playback-check.js`、`qa/real-popup-check.js`、`qa/probe-routing-check.js`。一次只运行一个，检查返回的 `pass`，不能仅凭 CLI 退出码判断通过。
5. 真实弹窗脚本使用 action popup 的独立浏览器目标，不给 popup.html 预设 viewport。路由脚本会暂时固定备用节点并恢复设置；播放脚本会主动停止后台验证唤醒；仅在独立配置运行。
6. 截图复查标题、模式高亮、当前/目标节点、指标、可操作按钮和滚动。诊断复制测试将内容截留在弹窗内存，不覆盖系统剪贴板，不输出签名 URL。

更新用户需要覆盖原解压目录、在扩展管理页重新加载，然后刷新已有 B 站页。保留设置，升级首次重新获取可信测速缓存。
