## 实际 UI 与受控复现

- 前期独立 Edge 的真实工具栏弹窗检查通过：真实 1920×1080 播放标题、缓冲、进度；暂停后停止呼吸灯；减少动态效果；连续开关五次；正常 400×599，错误状态不超过 600px。原生工具栏宽度不是用网页预设宽度冒充。
- 自动弹出来自我们显式运行的原生 QA 脚本，不是扩展运行代码。收到用户反馈后关闭该可见测试窗口，后续仅使用静默、静音的 headless Edge。运行代码不调用自动打开弹窗、通知或注入播放面板，新增回归保护。
- 最新 `quiet-popup-check.js` 12 项通过。该检查使用正常渲染的扩展页面、受控活动标签页绑定，不是原生弹窗尺寸测试。明确注入八个节点、重测、清空结果和错误状态来复现显示边界：重测保留节点，旧结果标记“上次”，更新后保留滚动位置，未测项无虚构 Mbps，错误页脚可达。真实本页为 Akamai 直通，重测禁用，最新这次没有执行真实网络手动重测。
- 前期原生测试曾覆盖可测速来源的后台重测和取消；最终候选目录新增逻辑由上述受控样例及纯函数回归验证。不能把受控八节点宣称为实际发现的网络节点。
- UI 只在打开时每秒读取展示快照；播放灯与测速状态分离；标题使用文本节点，导航及陈旧快照不冒充当前播放。实际帧尺寸不冒充所选档位或帧率。
- 候选目录显示默认、已发现和已测节点，未测不能固定成可用节点；没有扩充默认测速池。Akamai 仍沿用 2.2.0 原始直通，没有跨 CDN 切换。

## 重测与卡顿的区别

独立、静音 headless Edge 对用户指定 `BV1V3Ye6zE6f` 完成一次冷启动 1080P 60 帧整段播放：183.77 秒播放结束，92 次两秒采样，无中途 waiting/stalled/seeking/pause/error；首尾各十秒以外缓冲最低 10.54 秒。79 个媒体请求约 131.3 MB，最高首包 168ms，非取消网络错误为零。实际来源为 B 站 Akamai 原始直通，因此未验证自动备用节点切换。headless 不等同于用户前台解码、渲染及网络条件；这次没有复现用户卡顿，不是其根因结论。

用户原始 2.2.0 ZIP 中，手动重测完成后也会发送 `retry-playback`，触发 150ms 回退；本版保留此机制。这可能产生短暂 seek，但不能由此认定用户卡顿的原因。节点列表消失是展示问题，与播放器缓冲卡顿不是同一个结论。
